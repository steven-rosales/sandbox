# Rust Basics

## 1. Learning objectives and conceptual map

By the end of this lecture, you should be able to:

1. Read and write Rust syntax fluently, including its type declarations, expressions, functions, control flow, and pattern matching.
2. Explain Rust's ownership system from first principles, and predict when code moves, copies, borrows, or drops a value.
3. Translate TypeScript object types and discriminated unions into Rust structs and enums.
4. Design functions that communicate ownership and mutability through their types.
5. Build and test a complete command-line program with Cargo.
6. Interpret Rust compiler errors and use them to repair incorrect programs.

**The conceptual model**
-> Rust source code: Types, functions, structs, enums, expressions.
-> Type checking: Are operations and data representations valid?
-> Borrow checking: Are ownership, aliasing, and reference lifetimes valid?
-> Compiled executable: Memory management without a tracing garbage collector.

The critical difference from TypeScript is not that Rust has stronger static types. TypeScript can express complex static types too. The difference is that Rust's type system also constrains ownership and access to memory. The compiler reasons about who may access an object, whether an acess amy mutate it, and whether referenced data will still exist.

This allows memory-safe properties to be checked at compile time without relying on a tracing garbage collector for ordinary safe Rust. It does not mean every runtime error or logical bug disappears.

## 2. Toolchain and execution model

### 2.1. Rust's development pipeline

| TypeScript                     | Rust ecosystem                       |
| :----------------------------- | :----------------------------------- |
| TypeScript compiler (`tsc`)    | Rust compiler (`rustc`)              |
| `package.json`                 | `Cargo.toml`                         |
| npm/pnpm                       | Cargo                                |
| `package-lock.json` / lockfile | `Cargo.lock`                         |
| `npm run ...`                  | `cargo run`, `cargo test`            |
| ESLint / Prettier              | Clippy / rustfmt                     |
| TS type checker                | Rust type checker and borrow checker |

Unlike ordinary TypeScript compilation, Rust compilation produces native machine-code executables without requiring a JavaScript runtime.

Install the Rust toolchain with `rustup`. Then, verify:

```bash
rustc --version
cargo --version
rustup --version
```

We use Rust 1.97.0 or newer.

## 2.2. The project lifecycle

```bash
cargo new 1-agent_router
cd 1-agent_router

cargo check
cargo build
cargo run
cargo test
cargo fmt
cargo clippy
cargo build --release
```

`cargo check` type-checks and borrow-checks a project without product a final executable, making it useful for rapid development. `cargo build` produces a binary, and `cargo run` builds and executes it.

A normal Cargo project contains:

```txt
agent_router/
├── Cargo.toml
├── Cargo.lock        # Generated by Cargo
├── src/
│   └── main.rs
└── target/           # Build artifacts
```

`main.rs` is the executable entry point. The compiler begins at the `main` function.

### 2.3. Dependencies

We'll use an external `rand` crate to generate random values in a guessing game. For example:

```toml
[dependencies]
rand = "0.10.1"
```

Cargo resolved compatible dependency versions, records selected versions in `Cargo.lock`, and downloads the dependencies when required. The book demonstrates `rand::rng().random_range(1..=100)` using `rand`'s prelude.

Our primary implementation will have zero external dependencies. This keeps the attention on Rust's langauge mechanics rather than third-party APIs.

## 3. Language fundamentals: TypeScript to Rust

### 3.1. Variables, immutability, and shadowing

Consider TS:

```ts
const count: number = 3;

let retries: number = 2;
retries = 1;

const label = "agent";
```

and now Rust:

```rs

let count: i32 = 3;

let mut retries: i32 = 2;
retries = 1;

let label: &str = "agent";
```

Rust's `let` is immutable by default. `let mut` permits reassignment or mutation through that binding, subject to the type and borrowing rules.

An important distinction for TS developers: `const` in TS prevents rebinding but does not deeply freeze and object. An immutable Rust binding also prevents ordinary mutation through that binding, but Rust's full guarantees depend on its ownership and reference rules; Rust can still support interior mutability through special types.

Rust has another powerful mechanism: shadowing.

```rs
let raw: &str = "42";
let raw: u32 = raw.parse().expect("integer expected");
```

The second `raw` is a new binding and may have a different type. This supports a declarative transformation pipeline: `input text -> parsed value -> validated valued -> domain object`. Instead of repeatedly mutating the same variable, we can create new immutable bindings for successive representations.

### 3.2. Static types and inference

Rust generally infers local types but requires explicit types in function signatures.

| Concept               | Rust type                         | Interpretation                       |
| :-------------------- | :-------------------------------- | :----------------------------------- |
| Signed integer        | `i8`, `i16`, `i32`, `i64`, `i128` | Fixed-width signed values            |
| Unsigned integer      | `u8`, `u16`, `u32`, `u64`, `u128` | Fixed-width unsigned values          |
| Machine-sized integer | `isize`, `usize`                  | Architecture-dependent width         |
| Floating point        | `f32`, `f64`                      | IEEE-754 floating point              |
| Boolean               | `bool`                            | `true` or `false`                    |
| Unicode scalar        | `char`                            | Not the same as one UTF-16 code unit |
| String slice          | `&str`                            | Borrowed UTF-8 text                  |
| Owned string          | `String`                          | Owned, growable UTF-8 text           |
| Tuple                 | `(i32, bool)`                     | Fixed heterogenous product           |
| Array                 | `[u32; 3]`                        | Fixed-size homogeneous sequence      |
| Unit                  | `()`                              | No meaningful returned value         |

The main distinction from TS's `number` is that Rust has multiple distinct numeric types. Rust does not automatically convert arbitrary numberic types to each other.

```rs
let x: u8 = 10;
let y: u32 = 20;

let z = x + y; // Type error

let z: u32 = u32::from(x) + y;
```

Integer arithmetic also has finite ranges. For example: $0 \le x_{u8} \le 255$.

In normal debug builds, integer overflow is checked and can panic; release builds ordinarily omit these overflow checks. For correctness-sensitive arithmetic, use explicit operations such as `checked_add`, `checked_mul`, or `saturating_add` instead of relying on overflow behavior.

### 3.3. Expression vs statements

Rust is expression oriented, which makes it pleasant for function-style programming.

```rs
fn classify(score: u32) -> &'static str {
    if score >= 80 {
        "high"
    } else {
        "normal"
    }
}
```

The final expression returns the value. Adding a semicolon changes that expression into a statement whose value is `()`.

```rs
fn square(x: i32) -> i32 {
    x * x // Returns i32
}
```

Compare:

```rs
fn broken_square(x: i32) -> i32 {
    x * x; // Evaluates to (), not i32
}
```

The second function does not compile: its declared return type is `i32`, but the body produces unit.

You can also use a block as an expression:

```rs
let capacity: u32 = {
    let base = 4;
    let replicas = 3;
    base * replicas
};
```

This is useful when a calculation needs temporary variables but should expose only its final result.

### 3.4. Functions and control flow

```rs
fn double(value: u32) -> u32 {
    value * 2
}

fn priority(score: u32) -> &'static str {
    match score {
        0 => "none",
        1..=5 => "low",
        6..=10 => "medium",
        _ => "high",
    }
}
```

`match` is an expression, not merely a `switch` statement. Its arms must produce compatible types when the result is used. We will examine this more in Section 5.

Rust provides `if`, `else`, `loop`, `while`, and `for`. Conditions must be Boolean, there is not TS-style implicit truthiness.

```rs
let values: [u32, 3] = [2, 4, 6];
let mut total = 0;

for value in values {
    total += value;
}

assert_eq!(total, 12);
```

`loop` can return a value through `break`:

```rs
let mut counter = 0;

let answer = loop {
    counter += 1;

    if counter == 3 {
        break counter * 2;
    }
};

assert_eq!(answer, 6);
```

A `while` loop evaluates its Boolean condition before each iteration. `for` traverses iterable values. A loop label such as `'outer:` can identify which nested loop a `break 'outer` or `continue 'outer` targets.

### 3.5. Parsing values and handling absence or failure

Chapter 2 introduces two particularly important libraries types: `String` and `Result`.

```rs
let raw = "42";

let parsed: Result<u32, _> = raw.parse();

let value: u32 = match parsed {
    Ok(number) => number,
    Err(_) => 0,
};
```

`Result<T, E>` means an operation either succeeds with `T` or fails with `E`. It is Rust's typed alternative to relying only on thrown exceptions.

`expect("message")` extracts a successful value but panics on failure, so it is useful for examples and cases where failure genuinely cannot be tolerated. Recoverable input errors should normally be handled explicitly.
