# 20.2 Breadth-First Search

## Python Pseudocode

An adjacency-list graph looks like this:

```python
graph = {
    "s": ["a", "b"],
    "a": ["s", "c"],
    "b": ["s", "c", "d"],
    "c": ["a", "b"],
    "d": ["b"],
}
```

The keys are vertices, and each value lists the outgoing neighbors of that vertex.

```python
class Queue:
    def __init__(self):
        self.items = []
        self.head = 0

    def enqueue(self, value):
        self.items.append(value)

    def dequeue(self):
        if self.is_empty():
            raise IndexError("dequeue from empty queue")

        value = self.items[self.head]
        self.head += 1
        return value

    def is_empty(self):
        return self.head == len(self.items)


def bfs(graph, source):
    distance = {vertex: float("inf") for vertex in graph}
    parent = {vertex: None for vertex in graph}

    distance[source] = 0
    queue = Queue()
    queue.enqueue(source)

    while not queue.is_empty():
        vertex = queue.dequeue()

        for neighbor in graph[vertex]:
            if distance[neighbor] == float("inf"):
                distance[neighbor] = distance[vertex] + 1
                parent[neighbor] = vertex
                queue.enqueue(neighbor)

    return distance, parent
```

The queue keeps a `head` index instead of calling `pop(0)`. Removing index `0` from a Python list shifts every remaining item and costs $O(n)$, while advancing `head` costs $O(1)$. Appending to the tail is also $O(1)$ amortized.

`distance[neighbor] == infinity` means that the neighbor has not been discovered. This replaces CLRS's white, gray, and black colors with one practical test.

A vertex must be marked as discovered **when it is enqueued**, not later when it is dequeued. Otherwise, several neighbors could enqueue the same vertex and do repeated work.

## A Small Trace

Running BFS from `s` on the graph above produces:

| Wave | Newly discovered | Queue after the wave |
| ---- | ---------------- | -------------------- |
| $0$  | `s`              | `a, b`               |
| $1$  | `a, b`           | `c, d`               |
| $2$  | `c, d`           | empty                |

The final distances are:

$$
d(s)=0,\quad d(a)=d(b)=1,\quad d(c)=d(d)=2.
$$

There are two shortest paths to `c`: `s -> a -> c` and `s -> b -> c`. BFS records whichever parent discovers `c` first. Therefore, adjacency-list order can change the BFS tree, but it cannot change the shortest distances.

## Problem 1: Divide Wrestlers Into Two Rival Groups (20.2-7)

### Problem

Treat each wrestler as a vertex and each rivalry as an undirected edge. We want to divide the vertices into two groups so that every edge crosses between the groups.

This is exactly the question of whether the graph is **bipartite**.

### Intuition

Start one wrestler as group $0$. Its rivals must be group $1$, their unassigned rivals must be group $0$, and so on. BFS layers naturally alternate parity:

```text
even distance from source -> group 0
odd distance from source  -> group 1
```

If an edge ever connects two vertices in the same group, the required division is impossible. We must start a new BFS for every unvisited vertex because the graph may have multiple disconnected components.

### Python Pseudocode

```python
def bipartite_groups(graph):
    group = {}

    for start in graph:
        if start in group:
            continue

        group[start] = 0
        queue = Queue()
        queue.enqueue(start)

        while not queue.is_empty():
            vertex = queue.dequeue()

            for neighbor in graph[vertex]:
                if neighbor not in group:
                    group[neighbor] = 1 - group[vertex]
                    queue.enqueue(neighbor)
                elif group[neighbor] == group[vertex]:
                    return None

    return group
```

If the function returns `None`, no valid assignment exists. Otherwise, the returned dictionary gives every wrestler's group.

### Why It Works

The invariant is that every examined edge has endpoints in opposite groups. Assigning a new neighbor the opposite group preserves this condition. Finding an already-assigned neighbor in the same group proves a contradiction: that edge requires the neighbor to have both groups at once.

Equivalently, the conflict reveals an odd-length cycle, which cannot alternate cleanly between two groups.

Each component receives one BFS, so the runtime is $O(V+E)$ and the extra space is $O(V)$.

## Problem 2: Find the Diameter of a Tree (20.2-8)

### Problem

The diameter of a tree is the largest shortest-path distance between any two vertices.

### Intuition

Use two BFS runs:

1. Start from any vertex $s$ and find a farthest vertex $a$.
2. Start from $a$ and find a farthest vertex $b$.
3. The distance from $a$ to $b$ is the tree's diameter.

The first BFS walks us to an extreme end of the tree. The second measures from that extreme end to the opposite extreme.

### Python Pseudocode

```python
def farthest_vertex(tree, source):
    distance = {source: 0}
    queue = Queue()
    queue.enqueue(source)

    while not queue.is_empty():
        vertex = queue.dequeue()

        for neighbor in tree[vertex]:
            if neighbor not in distance:
                distance[neighbor] = distance[vertex] + 1
                queue.enqueue(neighbor)

    farthest = source
    for vertex in distance:
        if distance[vertex] > distance[farthest]:
            farthest = vertex

    return farthest, distance[farthest]


def tree_diameter(tree):
    start = next(iter(tree))
    endpoint, _ = farthest_vertex(tree, start)
    other_endpoint, diameter = farthest_vertex(tree, endpoint)
    return endpoint, other_endpoint, diameter
```

### Why It Works

A tree has exactly one simple path between every pair of vertices. Starting from an arbitrary vertex, a farthest vertex must lie at an extreme: if the path could continue farther away, then it was not farthest. More formally, comparing the unique paths with any diameter path shows that the first BFS reaches an endpoint of some diameter.

Once BFS starts from that endpoint $a$, no vertex can be farther from $a$ than the opposite endpoint of a diameter. Therefore, the second farthest vertex $b$ gives a longest path $a \leadsto b$.

Each BFS costs $O(V+E)$. A tree has $E=V-1$, so the total runtime is $O(V)$ with $O(V)$ extra space.

## What to Retain

- BFS means **distance layers**, not merely "use a queue."
- FIFO processing makes distances leave the queue in nondecreasing order.
- First discovery gives a shortest path only for unweighted or equal-weight edges.
- Mark a vertex when enqueuing it.
- `distance` answers how far; `parent` reconstructs how to get there.
- One BFS explores only the source's connected component.
- Common BFS applications include shortest paths, connected components, bipartite testing, tree distances, and multi-source spreading problems.
